## ⚠️ 更正：logo 截断 bug 确认并修复（龙兄折叠屏实拍截图证伪上文"完整"结论）

## ⚠️ 移动端顶部时钟+天气胶囊空白（根因已定位并修复，commit 97c80ff5）
- **现象**：龙兄报 iOS/Android 上 sheyang-weather.html 顶栏时钟 `#navClock` 与天气胶囊 `#navWeather` 不显示；本地 Playwright(390px) 却正常（navClock='17:46'、navWeather='19°'）。
- **根因**：全站 205 个 static 页里 203 个给 `js/app.js` 引用**没带 `?v=` 缓存戳**（仅 2 个有）。iOS/Android 把「加入该功能前」的旧版 app.js 按相同 URL 长期缓存、不肯重新拉取 → 旧版无这俩功能 → 空白。佐证：页内时间由带 `?v=20261011` 的 sheyang-weather.js 渲染故正常，恰好印证「缓存戳缺失」这一个点。CSP 已放行 open-meteo（connect-src 含 api.open-meteo.com），不是 CSP 拦的；app.js 本身无 Safari 不兼容语法。
- **修复**：为 app.js 及 interactions/search/share/bookmark/obfuscate-email/board-nav 共 7 个全局脚本在全部引用处补 `?v=YYYYMMDD`（日期取各文件 git 最后改动日，统一且规避 guard_v_param 致命 ERROR）；部署由 bump_v_hash 转内容哈希 `?v=h...`，以后脚本一改自动破缓存。Playwright 移动端实测 4 页（射阳气象/天气/紫砂/首页）均 navClock 有值、navWeather 显示真实温度、0 pageerror。
- **CI 关键事实补**：bump_v_hash.py 只处理源码里写成 `?v=YYYYMMDD` 的引用，裸 `js/app.js` 会被它忽略 → 移动端按同 URL 缓存旧版、部署更新后也不刷新。漏戳＝埋「改了跟没改一样」的地雷，且 guard_v_param 只查一致性+文件存在（漏戳不致命，仅 WARNING），必须人工带查。
