我的知识管理 & 效率方法

怎么攒素材、怎么做笔记、怎么把这个站搭起来并一直更新

一句话定位：知识管理不是为了「存得多」，而是为了让以后用得上——收集要轻、整理要勤、淘汰要狠。下面是我正在用的框架，通用方法都注明了出处，具体实践只是我自己的习惯，照着改就好。

1信息收集：把「看到」变成「留得住」

信息每天都在涌进来，但绝大多数看完就忘。收集阶段的目标只有一个：降低记录成本，让好东西不溜走，又不至于被信息淹没。

通用做法
  • RSS 订阅：用 RSS 阅读器聚合常看的新闻源、博客与技术周刊，绕过平台的算法信息流，自己决定看什么。
  • 网页剪藏 / 稍后读：遇到有用网页，存成纯文本摘录或加进稍后读，而不是一直开着几十个标签页「下次再看」。
  • 随手记收件箱：任何想法立刻丢进一个收件箱（手机备忘录、纯文本文件都行），定期再整理，避免「记了就忘、忘了再搜」的循环。
  • 随手标注来源：每一条素材都顺手记下出处，日后引用、核对都省事。

核心原则：收集时不做判断，只管「收进来」；判断留到整理阶段。

2笔记方法：通用方法论 + 一点我的实践

笔记方法有很多流派，下面两个是公认、有出处的通用方法，我也在用它们的思路。

卡片笔记法（Zettelkasten）

由德国社会学家卢曼（Niklas Luhmann）发展而来。核心是写「原子化」的小卡片——每张只讲一个想法，并用编号彼此链接，让卡片连成一张知识网络，而不是一堆互不相关的文档。这是经过长期实践验证的通用方法论。

第二大脑（Building a Second Brain）

由 Tiago Forte 提出，强调把信息外化到一个可靠的系统里，减轻大脑负担，并用 CODE 原则组织：Capture 收集、Organize 组织、Distill 提炼、Express 表达。同样属于通用方法，有兴趣可查阅其原著。

⚠ 说明：以上两种方法为公开、通用的知识管理方法，并非本人原创；以下实践才是我自己的习惯，仅供参考。
我自己的实践
  • 纯文本优先：用 Markdown 存「永久笔记」，能跨工具检索、长期不坏。
  • 链接代替文件夹：少用层层嵌套的分类，多用双向链接把相关想法串起来。
  • 先一句话卡片：重要的想法先写「一句话卡片」，确定值得留再扩写成完整笔记。

3知识库搭建：这个龙兄知识库是怎么来的

你正在看的这个站，本身也是我知识管理的一部分——把零散的笔记、素材沉淀成一个能长期访问的站点。

  • Hugo + GitHub Pages：用静态站点生成器 Hugo 产出纯静态页面，托管在 GitHub Pages。没有数据库、加载快、可长期存档，内容都在 Git 里，方便回溯。
  • 双主题：站点内置深 / 浅两套配色，用 CSS 变量切换，读者可一键切换，也尊重系统配色偏好。
  • 保持更新：内容以纯前端 / 纯文本方式维护，再配合自动化脚本批量更新部分数据，减少手工重复劳动，让「一直更新」变得不那么累。
  • 纯前端工具：天气、查询等小工具都尽量做成无需后端的纯前端实现，部署简单、维护成本低。

思路比工具重要：先把内容沉淀下来，再慢慢让更新流程自动化，别一上来就被搭建本身拖垮。

4定期复盘：别让知识库变成「信息坟场」

只进不出，知识库迟早会变成堆满过期内容的仓库。复盘的目的就是定期做减法。

  • 周回顾：每周花一点时间扫一遍「收件箱」和本周笔记，把值得长期留存的整理进知识库，临时的一律归档或删掉。
  • 月回顾：检查哪些主题还在关注、哪些已经过时；明确标注或淘汰不再适用的内容。
  • 淘汰过时内容：对已完成、已弃用或已失效的内容，不强行保留，直接标注「过期」或删除，保持库里都是还能用的东西。

复盘的产出不是「又整理了多少」，而是「哪些该扔了」。

5效率工具：思路比具体软件更重要

这里不推荐任何具体付费软件——适合别人的不一定适合你。下面几点是选工具时的通用思路。

  • 本地优先：能离线用、数据握在自己手里的工具优先，减少对云端的依赖。
  • 纯文本优先：能用纯文本（.md / .txt）就不用专有格式，便于长期保存、跨工具检索、不怕厂商停服。
  • 少依赖：工具链越短越好，核心就「收集—整理—回顾」三步，不为折腾工具本身花太多时间。
  • 适合自己最重要：方法没有银弹，挑一个你能坚持下来的，比追新、追全更重要。

本页为个人方法总结，通用方法（如卡片笔记法、第二大脑）已注明出处；具体实践为本人经验，供参考。
